# Compatibility matrix

What this build actually supports, and what it does not. Everything listed as
"not supported" is rejected rather than best-effort.

| Integration / protocol | Status | Conditions / limitations |
|---|---|---|
| OAuth-protected HTTP access | Supported (resource server + headless and interactive clients) | With `OAUTH_ISSUER`, `OAUTH_AUDIENCE` and a JWKS source configured, bearer tokens are validated as JWTs: EdDSA / RS256 / ES256 signatures against the issuer keys (`OAUTH_JWKS_FILE` or `OAUTH_JWKS_URL`, refetched on an unknown `kid` at most once per 10 s), `iss`, canonical `aud`, an RFC 8707 `resource` claim that must include the configured audience, `exp`/`nbf` with 30 s skew, and scope mapping (`scope` or `scp`); the issuer's `workspaces` claim decides which workspaces the principal may act in. `GET /.well-known/oauth-protected-resource` advertises the issuer, and a 401 carries a `WWW-Authenticate` challenge pointing at it (RFC 9728). Unknown algorithms, unknown kids, and unsigned tokens are rejected; the static development keys stop authenticating when `NODE_ENV=production`, which also refuses to start without an issuer (§7.3). The bundled client (`packages/mcp-client-shim`, `oauth:` option) discovers both metadata documents, sends the RFC 8707 `resource` indicator, checks the issuer binding in both directions, caches the token to just before expiry and refreshes once on a 401. Headless agents use `client_credentials`; interactive clients use Authorization Code + PKCE via `beginAuthorization()` and `createPkcePair()` (S256, state, code exchange, refresh-token rotation). A static bearer token requires the explicit `authProfile: "development"` shim option. Not implemented: token introspection. |
| Static development bearer tokens | Test profile only | `API_KEY` / `APPROVER_KEY`; refused at startup in production configuration. The shim requires `authProfile: "development"` before accepting a static `token`. |
| MCP client to gateway, Streamable HTTP revision `2026-07-28` | Supported (subset) | `server/discover`, `tools/list`, `tools/call` only. Per-request `_meta.io.modelcontextprotocol/protocolVersion` and `clientCapabilities` are required; `MCP-Protocol-Version`, `Mcp-Method` and (for `tools/call`) `Mcp-Name` headers must match the JSON-RPC body. `tools/list` returns namespaced `alias__tool` names with `ttlMs`, `cacheScope`, `resultType: "complete"`, and only entries the active signed bundle carries. Everything else - resources, prompts, subscriptions, sampling, elicitation, roots, Tasks, Apps, unknown methods - is rejected and never forwarded. No server-initiated stream (GET returns 405). |
| Signed policy enforcement | Supported | Enforcement reads only the active `policy_versions` row for the target project: content hash, Ed25519 signature over RFC 8785 bytes, key id recomputed from the pinned key, retired keys refused, bundle/row version and previous-hash agreement, project/workspace agreement, and rollback/fork/history-gap detection against the gateway's per-project accepted-version anchor (`GATEWAY_STATE_DIR`). No active version means `503 policy_unavailable` for calls and `POLICY_UNAVAILABLE` for `tools/list`. Publishing is operator-side (`tools/policy-publisher`); drafts never enforce. |
| Tool-definition pin coverage | Supported | The pin covers name, title, description, input and output schemas, annotations, icons, execution hints, and allowlisted `_meta` keys (`TOOL_PIN_META_ALLOWLIST`), hashed over RFC 8785 canonical JSON. External `$ref` values, schemas beyond the depth/node/reference bounds, and oversized definitions are never pinned; a previously trusted pin that gains one is quarantined. Changed definitions bump a pin version and quarantine until reviewed and re-published. |
| Audit chain verification | Supported | `POST /v1/audit/verify` recomputes every event hash and checks every link; the table is append-only at the database layer since migration 022. Since migration 028, events carry their workspace plus a per-workspace sequence; since migration 033 (`hash_version = 3`) the hash also covers the event ID and sequence. `hash_version = 1`/`2` rows still verify with their original formulas, so an upgraded chain spans all three formats. A prefix read reports `truncated`. Checkpoints are created, exported, and pruned only by the operator CLI (`pnpm audit:checkpoint`): the Ed25519 private key stays on the operator host, and the gateway receives only the public key for verification. Pruning deletes through the checkpoint's exact cutoff event and is restricted to the retention role; it requires the signed artifact plus an explicit external receipt. The signed v3 payload records the per-workspace segment heads, and the verifier reports missing sequences and `empty`/`complete`/`anchored`, so a partial history is never labelled fully verified. `pnpm audit:verify` checks an exported checkpoint plus its events offline; artifacts produced after a prune also carry the prior signed checkpoint as their `anchor`, and the verifier checks that signature before using its workspace heads. |
| Approval retry contract | Supported (in-gateway) | `tools/call` retries match a durable approval by `_meta.io.traceguard/logical_request_id` + authenticated caller. A call that needs approval without that metadata is refused with `APPROVAL_CLIENT_REQUIRED`. Server states: `pending`, `approved`, `rejected`, `expired`, `claimed` (durable short-lived claim; an expired lease without a recorded execution intent returns to `approved`), `executing`, `response_received`, `outcome_unknown`, `policy_invalidated`, `tool_quarantined`. The request hash binds caller, server, tool, canonical args, logical request id, and the tool-definition pin. A crash or timeout after dispatch yields `outcome_unknown` and is never retried. The certified client is `packages/mcp-client-shim` (`approval-client-profile: 1`); its tests pin the retry and terminal semantics. The human queue and decisions are served on the gateway's control listener (`GATEWAY_CONTROL_PORT`, default 8093), not the agent port, and take the `approve` scope itself — `admin` does not shortcut it. |
| MCP upstream server, Streamable HTTP | Supported | Registered servers only; egress allowlist, destination checks at register/discover/call, gateway-owned upstream credentials. Definitions are pinned and drift quarantines the tool. |
| MCP stdio upstream | Not supported | Unrepresentable in the schema and rejected; the gateway never spawns local processes. |
| Older MCP protocol revisions | Not certified | The gateway requires `2026-07-28` and rejects other versions with an explicit error. |
| OAuth-protected MCP access (RFC 9728 / RFC 8707) | Supported | The gateway serves RFC 9728 protected-resource metadata, validates issuer, audience, expiry, scopes, and the RFC 8707 `resource` claim against the configured audience, and never forwards an inbound bearer upstream. The client shim's `oauth:` option performs discovery, token request, and refresh; it supports `client_credentials` and Authorization Code + PKCE. Static keys are refused when OAuth is configured in production, and static shim tokens require `authProfile: "development"`. |
| Static development bearer tokens | Dev profile only | They keep working in development. With `OAUTH_ISSUER` + `OAUTH_AUDIENCE` + a JWKS source set and `NODE_ENV=production`, the static `API_KEY`/`APPROVER_KEY` are ignored; unmet requests get `401` with `WWW-Authenticate: Bearer resource_metadata=...`. |
| OTLP/HTTP traces, protobuf encoding | Supported | Trace signal only. Responses follow the collector contract: full acceptance returns an empty `ExportTraceServiceResponse`, rejections return `partial_success` with rejected-span counts and reasons. Body/span/attribute caps, a 24-hour late window, and a per-caller span rate limit (429) apply; see `docs/configuration.md`. |
| OTLP/HTTP JSON | Supported (extra) | Same mapping, limits, and partial-success semantics as protobuf. |
| OTLP/gRPC | Not supported directly | A Collector can translate to the OTLP/HTTP endpoint. |
| OpenTelemetry GenAI attributes | Best-effort mapping | A documented subset maps to columns; unknown attributes are bounded in count and length and never treated as security inputs. Stored spans carry `received_at`, `clock_skew` (future-dated starts or negative durations), and `parent_state` (`resolved`, `unresolved`, later `orphaned`). |
| Provider token usage | Supported when present | Missing usage or unknown price yields `NULL`, never zero. |
| @modelcontextprotocol/sdk | `^1.32.1` | Used as the upstream client only; the agent-facing surface is implemented in `apps/api/src/mcp.ts`, not by the SDK server classes. The installed version is pinned in the lockfile and exercised by the protocol tests. |
