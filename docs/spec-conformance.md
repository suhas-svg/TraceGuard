## Known gaps (read this first)

1. **The §21.16 checkpoint demo needs operator keys.** The checkpoint/prune path is implemented and tested (`apps/api/migrations/029_audit_checkpoints.sql`; `POST /v1/audit/checkpoints`, `POST /v1/audit/prune`; the verifier anchors a chain whose broken first link is covered by a valid checkpoint; `apps/api/tests/integration.test.ts` → “anchors a pruned audit chain with a signed checkpoint”), The checkpoint payload is now v2 with per-workspace segments, `GET /v1/audit/checkpoints/:id/export` produces the external artifact, prune requires an `external_ref` receipt, and `npm run audit:verify` verifies an exported segment offline. The dev compose profile does not set `AUDIT_CHECKPOINT_KEY`/`AUDIT_CHECKPOINT_PUBLIC_KEY`, so the live walk must export them first.
2. **Remaining open items (after the Phase 1 round):** none in the must-have set. FR-010 `path_within` now requires a server- and tool-scoped rule plus a pinned executor attestation (`io.traceguard/path-confinement`); the gateway refuses un-attested or out-of-root constraints, the publisher refuses to sign them, and the reference executor resolves real paths and blocks traversal and symlink escapes. FR-021 correlates `run_id`/`span_id`/`request_id` from gateway decisions and approvals into the trace view (migration 032, `/v1/decisions` filters, Decisions panel). The previously listed sub-paths are covered: `approval_binding_mismatch`, the workspace cap, `Mcp-Name`, `Cache-Control: no-store`, policy-storage-down (`approvals.test.ts`, `mcp.test.ts`, `fail-closed.test.ts`), the quarantined-tool and dropped-pin invalidation variants (`approvals.test.ts`), and the audit-write outage (`fail-closed.test.ts` plus `tests/faults/run.mjs`).
3. **The live network/upstream demo items are compose-shaped.** `mock-tools` publishes no host port by design, so the upstream-side checks run from inside the compose network (`npm run test:security`, the e2e suite); §21 items 3, 6–13, 17 require the stack up (`docker compose up -d --build --wait gateway mock-tools agent api`).

Performance targets NFR-001..003 are now a gate: `scripts/bench.mjs` prints PASS/FAIL per target and exits non-zero on any miss (measured on this host against the documented hardware: gateway overhead 7ms, dashboard 25ms, ingest 67ms p95 against the 100ms / 500ms / 3s budgets). The §21.5 shim walkthrough now exists as `examples/certified-agent/`. Additional smaller gaps are listed inline in the tables.
