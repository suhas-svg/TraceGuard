## Known gaps (read this first)

1. **The §21.16 checkpoint demo needs the operator key.** The checkpoint lifecycle is operator-only, not a gateway route: `pnpm audit:checkpoint -- create` signs an exact prefix and writes the artifact, and `pnpm audit:checkpoint -- prune` re-verifies it and calls the retention-only prune function. Migration `033_audit_integrity.sql` implements v3 hashing (event ID + per-workspace sequence), durable chain state, pruning through the checkpoint's exact cutoff event, and a prune receipt. The gateway holds only `AUDIT_CHECKPOINT_PUBLIC_KEY` for verification; the private key stays on the operator host. `pnpm audit:verify` verifies an exported segment offline. `pnpm demo` generates the Ed25519 checkpoint key pair under `.demo-keys/` (gitignored), passes only the public key to compose, and `pnpm demo:audit` performs create → offline verify → refused tampered prune. A manual `docker compose up` needs only `AUDIT_CHECKPOINT_PUBLIC_KEY`; pruning additionally needs the operator CLI and `DATABASE_URL_RETENTION`.
2. **Open must-have and independent-audit items (2026-10-21):** the project/principal layer now exists (migration 038): `projects`, `agent_principals`, and `ingest_api_keys`; `project_id` on MCP servers, policies, approvals, policy decisions, runs, and budgets; a default-project backfill and workspace trigger; project-scoped approval dedup/caps; `/v1/projects` CRUD, per-project ingest-key lifecycle, agent-principal management, and `/v1/whoami`; OAuth subject→AgentPrincipal mapping; and separate `tgi_` ingest keys refused on MCP/control/admin routes. The DB-role round (035–037) moved approval transitions to `approval_owner` procedures, publisher trust/activation to `policy_owner` procedures, and server/pin/policy admin writes from the gateway to the API. Migration 039 now scopes signed policy versions and active pointers by project and gives audit events project attribution with v4 hashes; signed trust keys remain workspace-scoped by design. **Remaining after the 2026-10-23 credential/pin/REST/identity/server-config round:** the pnpm workspace, frozen lockfile, and Phase 0 ADRs are now in place; the §5.4 layout deviation is an accepted, documented decision ([ADR-0009](adr/0009-repository-layout.md)), and the product-name release gate remains open ([ADR-0007](adr/0007-product-name.md)). In OAuth mode, local registration, login, user/key creation, and membership grants now return 403 `external_identity_required`; local API keys are refused by principal resolution, and local dashboard sessions are treated as expired. The local identity plane is development-only when no issuer is configured. Migration 042 now gives tool definitions immutable pin versions with a candidate → review → signed-publication lifecycle; migration 043 replaces plaintext `auth_secret` with a validated `secret_ref` resolved by the gateway; and migration 044 adds the §14 server-draft/disable routes. The §14 paths for MCP servers, server drafts, policy drafts, policy decisions, redacted approvals, run spans, and PATCH budgets are now present. The policy-draft routes alias the existing versioned `policies` table, the server-draft export is an unsigned handoff, and the API no longer resolves `secret_ref` at all: the admin discovery call is delegated to the gateway's internal listener, which reads the server row, resolves the credential in its own process, and returns only tool definitions ([ADR-0010](adr/0010-credential-custody.md)). The signed active server manifest is now implemented: migration 045 adds `signed_bundle_version`, the publisher stamps every project server inside the publish transaction, the gateway refuses a stale or unsigned server, and MCP `tools/list` hides it. Pre-upgrade rows stay unsigned and fail closed until the next successful publish. FR-002 implements ACPKCE, RFC 8707 `resource` validation, and the development-only static-token gate; FR-016 uses server-side sessions with CSRF and no dashboard dispatch shortcut; FR-024 and NFR-008 are implemented. See `docs/independent-spec-audit-2026-10-21.md` for the evidence. The earlier FR-010/FR-021/FR-011/FR-026/NFR-006/007/009 evidence notes remain valid. Migration 046 now closes the remaining direct API writes to trusted tool state (pin/server-tool transitions run as `policy_owner` procedures; the API lost `UPDATE` on those tables and `DELETE` on runs/spans), and migration 047 removes the pricing-timestamp precision race. The gateway now also supports per-tool-call holds: with `TOOL_CALL_RESERVATION_MICRO` above zero it reserves that amount against every covering run/agent block budget before dispatch (all-or-nothing, audited, released on completion), and a crashed hold is settled at its reserved maximum. The default is 0 because tool calls do not themselves spend provider money. Project budget spend now treats a span with no matching price as unknown: a block budget refuses with `budget_unknown_usage`, and the list withholds the remainder (`spend_complete: false`, `remaining_micro: null`).
3. **The live network/upstream demo items are compose-shaped.** `mock-tools` publishes no host port by design, so the upstream-side checks run from inside the compose network (`pnpm test:security`, the e2e suite); §21 items 3, 6–13, 17 require the stack up (`docker compose up -d --build --wait gateway mock-tools agent api`).

Performance targets NFR-001..003 are now a gate: `scripts/bench.mjs` prints PASS/FAIL per target and exits non-zero on any miss (measured on this host against the documented hardware: gateway overhead 7ms, dashboard 25ms, ingest 67ms p95 against the 100ms / 500ms / 3s budgets). The §21.5 shim walkthrough now exists as `examples/certified-agent/`. Additional smaller gaps are listed inline in the tables.
