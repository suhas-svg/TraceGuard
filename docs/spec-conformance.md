## Known gaps (read this first)

1. **The §21.16 checkpoint demo needs operator keys.** The checkpoint/prune path is implemented and tested (`apps/api/migrations/029_audit_checkpoints.sql`; `POST /v1/audit/checkpoints`, `POST /v1/audit/prune`; the verifier anchors a chain whose broken first link is covered by a valid checkpoint; `apps/api/tests/integration.test.ts` → “anchors a pruned audit chain with a signed checkpoint”), but the dev compose profile does not set `AUDIT_CHECKPOINT_KEY`/`AUDIT_CHECKPOINT_PUBLIC_KEY`, so the live walk must export them first.
2. **Several security sub-paths are implemented but untested**, so they are only as good as code review: the `approval_binding_mismatch` branch, the project-level pending-approval cap (100), `Mcp-Name` disagreement on `tools/call`, and `Cache-Control: no-store` on approval responses. Database-storage-down fail-closed is also untested (only “no active signed policy” is).
3. **The live network/upstream demo items are compose-shaped.** `mock-tools` publishes no host port by design, so the upstream-side checks run from inside the compose network (`npm run test:security`, the e2e suite); §21 items 3, 6–13, 17 require the stack up (`docker compose up -d --build --wait gateway mock-tools agent api`).

Performance targets NFR-001..003 are now a gate: `scripts/bench.mjs` prints PASS/FAIL per target and exits non-zero on any miss (measured on this host against the documented hardware: gateway overhead 7ms, dashboard 25ms, ingest 67ms p95 against the 100ms / 500ms / 3s budgets). The §21.5 shim walkthrough now exists as `examples/certified-agent/`. Additional smaller gaps are listed inline in the tables.
